# Windose 紫系像素桌面 · 深色版 — 参考图程序取色报告

![色块](<swatches.png>)

本页所有 HEX 均为**程序取样**（Node 22 + sharp 直接读像素），不含目测值：

- **整体聚类**：每张图缩放到 200px 宽后做 k-means（k=8，k-means++ 初始化，40 轮迭代），保留全部像素、不做黑白过滤，占比为像素数比例。
- **定点取色**：先在原图上用像素扫描 / 局部放大定位元素边界，再取以该点为中心的 **5×5 区域中位色**；1–2px 宽的细线（窗口外框、骨架图边框、分隔线）取**沿线 5×1 中位色**，避免中位色被两侧底色吞掉。
- **文字色**：像素字体笔画只有 1–2px，5×5 中位色必然混入底色，因此改用**文字区域最暗 6–8% 像素的平均值**，表中已标注。
- 坐标均为**原图像素坐标**，完整数据见 `palette.json`；取样点位置自检见 `check.png`。

## 2. 观察：原作从浅到深是怎么映射的

1. **压暗不是等比变暗，而是「加紫 + 压平对比」。** ss-06 桌面底色 `#F7ECFC` → `#A292DD`：R −85、G −90、**B 只 −31**，色相从约 281°（粉紫）移到约 253°（蓝紫）。同一张图的锯齿底纹线 `#D3EBF7` → `#A48DDD`，与底色的差值从 ΔRGB(−36, −1, −5) 缩到 (+2, −5, 0)——**夜间形态把桌面锯齿纹理基本抹掉了**。深色主题要复刻这种观感，底纹必须以极低对比度（≤5/255）处理，而不是保留白天的青色线。

2. **强调色在深色下「保持甚至更饱和」，中性面才被牺牲。** 靛蓝方块 `#361DC3` → `#431CC3`（仅 R +13，几乎不动）；薄荷细条 `#A7EFE3` → `#85F2DD`（R 降 34、饱和度反而上升）；弹窗粉标题栏 `#EDC9ED` 与未压暗的 ss-03 / ss-05 活动窗口标题栏**同值**，说明压暗层没有动它。规律是：**强调色原样保留，只有中性面（灰、白、粉白底）被紫色 overlay 压暗**。（浅蓝信息条 `#CCE7F8` 在白天样本中找不到同类弹窗，无对照，按原值记录，不作为「未变」的证据。）

3. **中性灰会被染成蓝紫，证明夜间是「叠加紫色滤镜」而非「乘暗」。** ss-01 窗口标题栏 `#E2E2E0` 是纯中性灰（R≈G≈B），压暗后成 `#938CCF`：R 147 / G 140 / **B 207**，蓝通道多出 60。若是单纯乘系数降亮度，R≈G≈B 的关系会被保持；蓝通道单独抬升说明叠了一层偏蓝紫的混合层。这也是「紫系深色版」应当实现的着色模型。

4. **ss-02 与 ss-06 是两种不同的夜间，不能混用。** ss-02 的标题栏 `#DEDEDE`、正文 `#FDFDFD`、任务栏 `#F6DDFB` 与白天数值几乎一致，说明它**只有背景（两侧合成波夜色）是夜间，UI 本体没有压暗**；真正的整体压暗形态只有 ss-06。落地深色主题时应以 ss-06 的映射为准，ss-02 只用来取夜景背景色（`#F7E6FE` 桌面 + `#63CCEC` 霓虹青聚类）。

5. **两套暗色策略并存：像素桌面保留「靛蓝 + 薄荷」，暗色骨架换成「洋红」。** 浅色骨架（fandom default）的强调是蓝 `#527CE7` + 淡粉 `#F7E1FB` + 紫线 `#AB9ED8`；暗色骨架（fandom dark）把它整体换成洋红 `#FF42F1` / `#DF3AD9`，底色落到 `#000033` 与 `#002333`（深青），列表选中语义位也由薄荷 `#7CF0B1` 让位给洋红。而像素桌面自己的深色形态（ss-06）**仍然保留靛蓝 `#431CC3` 与薄荷 `#85F2DD`**。对 VRCX 主题的建议是走后者：以 ss-06 的「保留薄荷/靛蓝、只压中性面」为主，洋红仅作为暗色骨架一脉的次级强调备选。

- 参考图为 JPEG/WebP 有损压缩，像素边界存在抗锯齿混色；细线与文字类元素的取样值已注明取样方式，属该压缩条件下的可复现值。
