# 艺术主参考：紫系 SNS、NSO 像素窗与地雷装饰

更新：2026-10-11。**这份是新的主参考，不再以编辑器主题作为艺术方向。**

研究对象是图形、服饰纹样、直播背景与游戏界面的装饰语言；用途是迁移到 VRCX 现有三栏 CSS 主题。

**审阅范围：Lead 已亲自用 read_image 看完 `art-references/` 下全部 30 张下载图，以及用户上传图（含 4 个研究局部）。** 子任务另写的[逐张记录](<art-references/art-references.md>)也已读过；它的观察大体准确，但有几处迁移建议过头，在“对子任务报告的修正”一节纠正。

## 先看结论（2026-10-11 修订版三方向）

| 新方向 | 主要参考 | 值得做的部分 |
|---|---|---|
| **① Windose 紫系像素桌面（推荐）** | NSO 截图 01/03/06/08＋用户漫画图 | 浅紫桌面底；Win95 式窗框（靛蓝方块＋像素标题＋底部薄荷条）；评论列表式好友表（方块项目符号、整行选中填色、带强调线的表头、双色滚动条）；Poketter 式动态行；三段式弹窗＋紫色蒙层；像素心与点线 |
| **② 粉黑系带蕾丝（服饰浅色）** | aomaterial 全系＋ramuneya＋sozaino＋夢展望横幅 | 炭灰波瓣带做面板上下沿；系带柱＋结做详情封面两侧；结与框线相连；低对比符号底纹（心／结／十字／兔／创可贴）；**装饰色固定、底色可换**；参考品牌的灰粉、酒红、灰褐、黑 |
| **③ 小恶魔暗夜（深色）** | sozaino 小恶魔背景＋用户图紫黑格纹＋NSO dark 直播骨架 | 深色底＋蕾丝扇形边＋系带；紫黑格纹窄带；骷髅／心作为极淡点缀；洋红只用于激活与焦点 |

区别：①的识别点是“复古桌面窗口＋SNS”，②是“少女服饰的边饰”，③是“暗色小恶魔服饰”。①和②默认浅色，③给需要深色的用户；当前正式主题是深色，所以③不能省。

这里没有给定新的 HEX 或像素尺寸：截图能证明结构和视觉关系，但不能证明原作者的 CSS token、hover、焦点或响应式参数。后续数值由 VRCX 原型实测确定。

### U01-a · SNS 图文层级

![用户上传图局部：头像、用户名与 SNS 文字窗](<art-references/user-study-details/sns-window.png>)

- **观察**：淡紫实底、圆头像、姓名／ID 与正文分层；周围紫色细框，人物插画会跨在框外。
- **迁移**：右侧用户详情或活动卡片采用头像＋主名＋次级 ID 的层级；世界／用户原图片不滤色。只改 CSS，不凭主题把表格 DOM 改成社交网络。
- **舍弃**：原文字太淡，不用作正文对比度合格的例子；跨窗人物是海报构图，不能覆盖 VRCX 操作控件。

### U01-b · 像素爱心

![用户上传图局部：三枚像素爱心](<art-references/user-study-details/pixel-hearts.png>)

- **观察**：阶梯轮廓、粉色体块、浅色高光，三颗并排构成横向节奏。
- **迁移**：原创绘制自己的网格心形用于详情封面边缘／空状态／预览图；数量和排布按局部空间确定。

### U01-c · 标签包边与错位阴影

![用户上传图局部：胶囊标签与错位阴影](<art-references/user-study-details/capsule-label.png>)

- **观察**：奶白正文标签、紫轮廓、下右错位阴影，小粉标签接在上缘，还有指向性尖角。
- **勘误**：这块看不到前面所说的“内圈虚线”，主要是实线包边与错位阴影，不继续传播该观察错误。
- **迁移**：导航激活项／分组标题／主要 badge 可以借“标签贴在框上”的关系；保留原文和原 hit area，不画假 Tab 功能。
- **舍弃**：巨大胶囊加多层阴影不适合每一条数据行；旧英文标签和漫画标题不复制。

## N01 · NSO 桌面：统一外壳与不同内页

![NSO 桌面截图 01](<art-references/nso-steam-ss-01.jpg>)

参考出处：[游戏 Steam 页面](https://store.steampowered.com/app/1451940/)。文件标记为 Steam 截图；具体图片下载 URL 的子任务记录尚未落盘，不能据此认定许可。

- **观察**：灰色窄标题条＋紫色双轮廓，同一种外框包着浅色数值区、粉色聊天区和角色画面；桌面壁纸与侧边风景承担大图装饰，窗口内有自己的实底。
- **迁移**：VRCX 三栏可共享边框语言，但不必三个面板同色。右侧详情／弹窗标题可统一方形窄边；内容区留独立实底。这比全应用刷一层淡紫更有身份。
- **舍弃**：不加风景边栏挤占宽度；不添加压力／好感等游戏数值；不用游戏角色画面当主背景。
- **行为未知**：截图不能证明按钮 hover、键盘焦点、最小窗口尺寸；不能复制假窗口按钮替代应用真实动作。

## N02 · NSO 小弹窗：标题和功能层级

![NSO 桌面截图 02：小窗、选项与重叠层级](<art-references/nso-steam-ss-02.jpg>)

参考出处同 N01。

- **观察**：主体中间有白色内容小窗和更小的前景选择窗；活动窗标题带粉色，普通标题偏灰；功能区有清晰图标与正文留白。背后直播区域是黑底。
- **迁移**：弹窗标题与内容分开处理，前景浮层边框更明确；普通按钮、激活项、弹窗不要全部同一种亮粉。原生 dialog 仍只有真实 close 控件。
- **舍弃**：多窗叠压是游戏桌面玩法，不对 VRCX 的好友／日志表照搬；大图标布局不是数据行规格。

## N05 · NSO 图标图集：统一像素规则，而非全套替换

![NSO wiki 文件标记：桌面图标集合](<art-references/nso-fandom-desktop-icons-sheet.png>)

## A01 · aomaterial：结与框边的连接

![aomaterial 黑色缎带框](<art-references/aomaterial-jirai-bg-black-ribbon-frame.png>)

- **观察**：黑结在顶部向两侧延伸成缎带；边框在侧面系带处中断，下沿有翅膀与十字组合；粉底图案很淡。结不是独立孤零零盖在窗上，而是边框构造的一部分。
- **迁移**：右侧详情封面或大卡片采用“饰物与边框接头相连”；选中导航的缎带线与结同语言。
- **舍弃**：顶部大结占高很多，不放在 h-8 标题栏。多种符号重复背景不进入表格正文。

## A02 · aomaterial：波瓣是外壳，而不是正文纹理

![aomaterial 粉底与黑波瓣边](<art-references/aomaterial-jirai-bg-pink-scallop.png>)

- **观察**：黑色上下波瓣，左右局部交叉线及结，粉色大底保留中心空间。
- **迁移**：大卡片或详情封面局部波瓣，外层 dark 与内层粉色实底反差；窄区域换更简单的边线，不机械缩整张图。
- **舍弃**：上下连续波瓣不能默认放到每个表格行，滚动时会反复干扰阅读。

## R01 · ramuneya：系带不是一串孤立 X

![ramuneya 粉色系带背景](<art-references/ramuneya-jirai-lacing-pink.png>)

- **观察**：交叉线连续形成菱形，底端收成结；黑色波瓣外边配稀疏心与圆点，四角还有小心形。
- **迁移**：详情封面两侧／登录大卡片角部可以使用原创系带；只要一组主要装饰，别让小卡片也复制全部边框。
- **舍弃**：不把侧系带占用表格列间空间；原直播中心留白大，VRCX 无同等空间。

## S01 · sozaino：波瓣缝线与软糖心

![sozaino 粉色爱心和黑色缝线波瓣](<art-references/sozaino-jirai-heart-lace-16x9.png>)

- **观察**：两角斜向黑边含心形与白虚线，结扣连接斜带；爱心有软糖高光和边缘厚度，中心粉色圆点密度较高。
- **迁移**：卡片角部的窄缝线边＋独立结可有层次；心形可作为空状态或详情封面装饰。用自己的轮廓／高光，不照描本图。
- **舍弃**：高对比心形遍布主区会压过头像和名字；海报斜框不适合每个正置信息窗。

## S02 · sozaino：同构造不必只有粉黑

![sozaino 绿色与红棕色缎带蕾丝框](<art-references/sozaino-ribbon-lace-frame.png>)

- **观察**：与上一类构造相似，绿底、红棕花边、白描边，保留结／缝线／心／点。不是粉色素材。
- **迁移**：地雷感由构造组合带来，不只由一个粉色 token。紫系方案可保留同类结构而换成自定色板。
- **舍弃**：不因文件名有 ribbon 就把绿红色直接作为本项目配色；当前没有原图 CSS／HEX 实测。

## S03 · sozaino：宽带编织的层次

![sozaino 编织系带与粉色菱格](<art-references/sozaino-amiage-ribbon-bg.png>)

- **观察**：粉色菱格底、上下波瓣与点线、左右粗缎带交叉；缎带有色差构成压叠次序。空间里还有不同朝向的结与心。
- **迁移**：原创系带不只是两根斜线，要有可见压叠方向；用于封面边缘，比随机塞十字更像服饰。
- **舍弃**：粗带宽度无法在密集卡片里等比例保留；不复制原图所有结的排布。

## A03 · aomaterial：同一构造配 24 种底色

![aomaterial 地雷背景第 1 套 24 色](<art-references/aomaterial-jirai-bg-set1-sheet.jpg>)

![aomaterial 地雷背景第 2 套：黑缎带框 17 色](<art-references/aomaterial-jirai-bg-set2-ribbonframe-sheet.jpg>)

- **观察**：同一版式（波瓣边、×××、结、低对比符号底纹）换了粉、灰、黑、灰紫、灰蓝、肤色、酒红等底色；装饰色基本只有炭灰或白两种。竖版那套多了宝石心和菱形细格。
- **结论**：地雷感来自**构造**而不是某一个粉色。主题可以把装饰色固定为炭灰（深底时换白），底色单独成 token，以后出配色变体只改底色。这比给每个方向各写一套装饰更省事。

## D01 · 夢展望：真实地雷系品牌的配色

![夢展望 EC 横幅拼图](<art-references/dreamvs-ec-banners-sheet.jpg>)

![夢展望 PRICE DOWN 竖幅](<art-references/dreamvs-ec-pricedown-banner.jpg>)

来源：https://dreamvs.jp/ （版权：株式会社夢展望）。横幅含小尺寸模特照，只看版式和配色。

## 对子任务报告的修正

子任务的[逐张记录](<art-references/art-references.md>)观察部分基本可信，下面几条迁移建议我不采纳：

1. **“dark 直播图三色可直接当暗色变体骨架”**：那些 HEX 是目测估计，图里没有正文文字，无法验证对比度；深藏青＋洋红也更偏赛博。只作氛围参考。
2. **“右侧详情做成任务管理器式大数字＋/100 条形”**：VRCX 没有这类数值，主题不能凭空造统计。只有真实存在的数字字段可以借大号像素数字的样式。
3. **“左导航改成图标＋下方标签竖列”**：VRCX 导航是横向文字行，改成竖列图标网格要动布局，CSS 主题风险大，先不做。
4. **“自绘一整套 VRCX 功能图标”**：现有图标是内联 SVG，CSS 很难逐个替换；工作量和兼容风险都高，先保留原图标，只换颜色。
5. **“状态头像思路用于在线状态徽标”**：在线／忙碌／离线的颜色和形状是业务语义，不改。
6. **“彩虹渐变条用于特殊状态”**：同样涉及自造语义，不采纳。

## 可执行的风格 DNA：不再只换粉色

| 观察到的模式 | 迁移原则 | 我们可以制作的资产／组件 |
|---|---|---|
| 漫画图的紫黑格与淡紫 SNS 窗 | 外壳有身份、文字层级清晰 | CSS 格纹、头像边圈、姓名／ID 两级颜色；不增改数据结构 |
| NSO 各小窗同边框、内页不同 | 统一结构比统一所有底色更有识别度 | 自制窄双框、标题条、focus 边，保留真实功能按钮 |
| 像素爱心有阶梯轮廓和高光 | 像素化只落在小装饰，不降低正文可读性 | 自定网格心形／星形 SVG，中文仍用正常字体 |
| 结与边条相接，系带有收口 | 装饰具有构造关系，不随机贴图 | 新画结、波瓣／缝线 border strip、局部编织 SVG |
| 服饰纹样与阅读框分离 | 重图案留在封面或空隙 | 使用已验证 CC0 tile 或原创渐变纹样，表格行保持实底 |
| 素材站同一构造配几十种底色 | 装饰色固定、底色单独成 token | 炭灰／白两套装饰色，底色可替换，变体只改底色 |
| NSO 列表整行选中填色、表头强调线 | 选中态用实色块，不只靠细描边 | 好友表选中行、表头标签、双色滚动条 |
| NSO 弹窗三段＋紫色蒙层 | 层级靠分段底色，蒙层也带主题色 | dialog header／body／footer 分色，overlay 用主题紫 |
| 品牌站灰粉＋酒红＋灰褐＋黑 | 真实地雷系配色偏柔和成熟 | ②的色板参考，避免糖果霓虹粉 |

hover、disabled、error、键盘 focus、缩放和滚动属于待验证实现，不从静态艺术图编造行为。下一步若做原型，仍须比较同一份匿名数据，不再用不同编辑器代码截图凑效果。
