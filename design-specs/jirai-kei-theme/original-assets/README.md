# Original Jirai decoration assets

This is a source/specimen package for three unselected visual directions, not a published theme. S1–S11 are newly authored single-color SVG shapes. No reference image pixels, third-party assets, downloaded vectors, tracing, or auto-vectorization are included. Accent colors in `palettes.json` are testing swatches only, not an approved palette.

## Build

Requires Node.js 22+; no package installation is needed.

```sh
node build.mjs
# Or supply any alternate JSON object mapping palette names to hex colors:
node build.mjs ./your-palettes.json
```

`src/*.svg` produces compressed SVG files, `dist/jirai-assets.css`, and `dist/assets-report.json`. The CSS contains URL-encoded SVG data URIs (not base64), so it can be copied inline into a community theme CSS. Relative `url(./asset.svg)` paths are intentionally avoided: installed themes receive CSS text, not sibling asset files. The build checks that each asset uses integer viewBox dimensions divisible by four, that source art is one-color fill-only SVG, that pixel/dither assets declare `crispEdges`, and that size budgets are met.

- Per compressed SVG limit: 1.5 KiB.
- Combined URL-encoded SVG payload limit: 20 KiB.
- The generated CSS includes both M-mode `--jk-mask-*` variables and B-mode `--jk-bg-{palette}-*` variables baked from the provided palette JSON.

## Use mode M: token-recolorable mask

Good for fixed, non-scrolling edges. Add an absolutely positioned pseudo-element to an existing theme hook; do not add markup or cover controls:

```css
:root { --jk-deco: #4a3d61; }
.vrcx-0-titlebar { position: relative; }
.vrcx-0-titlebar::after {
  content: "";
  position: absolute;
  inset: auto 0 0;
  height: 8px;
  background: var(--jk-deco);
  -webkit-mask: var(--jk-mask-s1-s) repeat-x left bottom / 16px 8px;
          mask: var(--jk-mask-s1-s) repeat-x left bottom / 16px 8px;
  pointer-events: none;
}
```

Set `background-color` on the masked element (rather than relying on SVG fill) to recolor one-color art. Keep masks within padding/non-interactive space. Include both `-webkit-mask` and standard `mask` for WebView2 compatibility.

## Use mode B: palette-baked background for scroll containers

For dialog content whose overflow scrolls and clips pseudo-elements, use a baked image on the element itself, anchored to its box:

```css
[data-slot="dialog-content"] {
  background-image:
    var(--jk-bg-light-s1-s),
    var(--jk-bg-light-s1-s);
  background-repeat: repeat-x, repeat-x;
  background-position: left top, left bottom;
  background-size: 16px 8px, 16px 8px;
  background-attachment: scroll, scroll;
}
```

The `light` name above comes from this package's example `palettes.json`; use the variable names that your supplied palette JSON generated. Baked art is color-specific, so pass the palette JSON appropriate to a direction/mode during build. The dialog background surface should remain specified as a lower background layer/color by the consuming theme. Verify any production layering against the actual app; `specimen.html` demonstrates both modes but is not an application integration test.

## Regenerate sources and sheets

```sh
node gen.mjs          # rewrites the round-2 procedural sources in src/
node build.mjs        # dist/ + jirai-assets.css + assets-report.json
node sheet.mjs        # screenshots/assets-4x-sheet.png (4x, light and dark rows)
PLAYWRIGHT_BROWSERS_PATH=/tmp/dsh-theme-browsers node capture.mjs   # DPR 1/1.25/1.5/2
```

`capture.mjs` needs the Chromium build that lives in `/tmp/dsh-theme-browsers`; without the variable Playwright looks in `~/.cache/ms-playwright` and fails. Mode-B baked copies are generated only for the edge strips S1, S2 and S3.

## Specimen

Open `specimen.html` locally after running the build. It shows both a light and dark surface, an h-8 (32 CSS px) titlebar, active sidebar item, the S1–S11 motif sheet, mode M, and a content-overflow dialog decorated with mode B. Screenshots in `screenshots/` are generated by the Playwright capture script at DPR 1, 1.25, 1.5 and 2 (WebP). These are visual material checks, not VRCX runtime screenshots.
