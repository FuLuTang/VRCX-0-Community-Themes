原生 <input>：现状 vs 补上字段皮肤后

暗色主题页面中的并排示意。左侧普通原生文本输入保留 UA 外观；右侧仅为文本字段类型补上字段框。两边的专属控件和 slot 参照都使用当前主题规则。

页面暗底取自 theme.css tokens 的 --background: #16112a。注意：主题真实字段规则是 #201936 底、1px solid #6c5ce0 边、var(--jk-field-inset)（inset 1px 1px #16112a, inset -1px -1px #a294c8）；不是 #211a33/#8c71b0（后者用于其他控件/子部件）。为忠实展示现状，左侧文本类 input 强制采用 light UA 控件配色，避免浏览器暗色偏好掩盖常见的亮色输入框差异。

现状（未覆盖的原生 input）

仅有字体继承；不额外施加通用 input 外观。

type="text"

普通文本

背景：UA 亮色 →（现状保持）；右侧补为 #201936。

type="search"

搜索

边框：浏览器默认 → 右侧 1px solid #6c5ce0；独立搜索框才适用。

type="number"

数值

背景/边框：浏览器默认；右侧加字段盒子，保留原生步进器。

type="password"

密码

背景：UA 亮色 → 右侧 #201936；字符仍由浏览器遮蔽。

type="time"

已有字段规则

已经共用主题字段底框及原生时钟图标；两栏一致。

type="file"

保持专属处理

仅文件选择按钮套现有样式；整行保持原生文件名区与选择行为。

type="color"

保持专属处理

保留原生色板交互与专属 swatch 边框，不套文本框尺寸/阴影。

type="range"

保持专属处理

轨道/滑块有独立样式；文本框背景边框会破坏 slider 语义和命中区域。

[data-slot="input"]

皮肤参照

主题已有字段皮肤；与右栏参照相同。

补上字段皮肤后

普通文本字段使用主题已有 slot 字段声明作为视觉基线。

type="text"

普通文本

背景：UA 亮色 → #201936；边框：默认 → 1px solid #6c5ce0。

type="search"

搜索

加方角、内斜面阴影；置于 input-group 时应由外框负责。

type="number"

数值

字段底框统一；原生步进器及其交互仍保留。

type="password"

密码

暗底、紫边与内阴影；占位符沿用 #b9add9。

type="time"

已有字段规则

既有字段规则 + 浏览器时钟图标，两栏不产生新增差异。

type="file"

保持专属处理

不应用整框皮肤；避免文件名区和原生按钮布局变形。

type="color"

保持专属处理

保留 swatch 与原生调色器；文本框内阴影/填充会显得不合适。

type="range"

保持专属处理

继续使用范围控件专属轨道/滑块，不套字段框。

[data-slot="input"]

皮肤参照

保持与左栏完全一致；该控件原本就有皮肤。

客观权衡

修补的好处

  • 裸文本字段与组件字段视觉一致，减少同页混搭感。
  • 暗色页面不再出现突兀的白色/亮色字段块。
  • 焦点、占位符、边框和内阴影可统一到主题语言。

修补的代价

  • 这是外观变化，不属于严格等价改写。
  • 会新增相对当前基线的 CSS 差异和维护范围。
  • 把规则扩展到不合适的控件可能令 file/color/range 更难看或损害可用性。

此为自包含示意页，UA 原生控件会受浏览器与操作系统影响；文本类左栏采用浅色原生控件配色以清楚展示常见差异。slot 与 time 对照依据 theme.css 当前字段声明，不代表提议必然应合并到所有原生 input。
