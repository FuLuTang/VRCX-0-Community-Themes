副作用警示（待核对条件）

边框叠加与尺寸

  • fields-toolbar-r10 对 control 设 transparent / box-shadow:none，但该组 CSS 没有显式 border:0。
  • 运行时快照的 control utility class 中出现 border-0；若该 utility 生效，外框内不会再画一圈。若它未生效、被更具体规则覆盖，B3 外框方案可能出现内外双框或内容宽高变化。
  • 选项 B 将边宽从 1px 改 2px；可用空间、对齐与按钮接缝都可能变化。

特例与子部件

  • Chart（tools-ui-r9）有独立上下文：其外框样式由 tools-ui-r9 的 frame 规则提供，且 13 文件的通用选择器刻意排除 #chart toolbar；若统一改写 selector，需要确认排除逻辑。
  • BrowseHistory 有独立嵌套规则，当前只设外框颜色/动效文字项，通用 :where() 补上边色与阴影；若新增更具体 frame rule 可能改变此结果。
  • 普通 toolbar 的 addon 仅颜色；输入组按钮粉底 #ffb8e6、独立 1px inset，不应被误当成外框。
  • Feed chips 是更具体的 :has() 特例，border shorthand 会压过通用四边色。改 selector 或追加规则时要明确是否包含该特例。

待拍板清单

  1. 外框是否维持现状（A），还是也采用斜面（B），或只对齐四边色（C）？
  2. 若选 B，是否接受外框边宽 2px、背景改 #2a2147 和控件空间变化？
  3. Chart / BrowseHistory 是否继续保留各自上下文，或纳入统一规则？
  4. Feed 的 combobox-chips 外框是否跟随所选方案？
  5. input-group-button 是否继续保持粉底与独立 inset，不并入外框 B3？
  6. 需不需要显式保证 control 的 border:0（而不只依赖运行时 utility class）？
