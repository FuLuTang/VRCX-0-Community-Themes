Observed volatility
-------------------
- Live app content changes between visits: images replace skeleton SVGs; route lists
  change in length; profile/group rows and other data arrive asynchronously.
- App state is persistent: remembered route, expanded/collapsed sidebar, selected tabs,
  and status/control state differ between runs. `/login` redirects to the persisted
  last route; `/favorites/import/friends` redirects to `/favorites/worlds`.
- Animated/disabled controls are stateful: refresh buttons switch between running and
  idle; pulse animation and hover/disabled paints differ. Rewinding animations reduced
  one source of variance but does not freeze React/application state.
- A DOM path is now rooted at `<body>` (head script/style ordering no longer shifts the
  whole tree), and paths are unique within a snapshot. Remaining diffs are real runtime
  variability, not the original head-path indexing bug.

Largest changed-property counts (shared paths, aggregate):
  transform-origin 541; bottom 481; height 418; width 243; top 103; left 103;
  opacity 98; right 86; z-index 86; background-color 85; pointer-events 84.

Conclusion
----------
A single live-app capture is a useful observation, but repeated live captures cannot
satisfy an empty computed-style diff because the app's DOM/data/control state changes.
Do not hide these differences by silently excluding properties or unstable routes. The
user chose the exact-comparison remedy: local static replay fixtures freeze the rendered
DOM and its inline stylesheet inputs; baseline CSS and every refactor are compared against
the same captured states. Captures remain local/ignored because DOM and screenshots may
contain private VRChat account data.
