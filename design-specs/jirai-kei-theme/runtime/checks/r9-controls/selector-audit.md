# R9-B selector hit/miss audit

## Hit list

- **Toolbar segmented controls:** see [controls-r9.css](../../controls-r9.css). Outline ToggleGroups remain limited to `.vrcx-0-main-content .vrcx-0-page-toolbar`; items match both `[data-slot="toggle"]` and the `TooltipTrigger`-wrapped `[data-slot="tooltip-trigger"][aria-pressed]`, not the replaced inner slot. Their active decorative `::before` is suppressed only on selected outline items so the app's dark/input overlay cannot wash out the shared active face. Horizontal TabsLists now cover all page-scaffold descendants in main content, including both toolbars and bare lists. Fixture covers Activity overview/date range, Activity journey density, Friends locations, Game Log, My Avatars, Themes browse/installed, Gallery, Inventory, and a separate Relationship Graph visual screen.
- **Bare main-content tabs:** `.vrcx-0-main-content .vrcx-0-page-scaffold [data-slot="tabs-list"]:not([data-orientation="vertical"])` — hits the unwrapped TabsLists in CommunityThemesSection, GalleryTabs and InventoryPage as well as toolbar tabs. The three bare states are explicit fixture hits; their independent `tab-indicator` is hidden just like toolbar tabs.
- **Activity statistic cards:** `.vrcx-0-main-content .vrcx-0-page-scaffold:has(.activity-skin) .activity-skin section.activity-card` — hits the three exhibit sections under Activity `.activity-skin`. It changes the shell only; `--act-*` heat values and chart gradients are asserted unchanged.
- **My Avatars TileShell:** the page hook requires a toolbar tooltip-trigger containing `svg.lucide-list`; within that page it hits context-menu-trigger/group-card shells with a direct rounded-object button, the selected `ring-2` state, the top-left size-5 check, and direct icon-xs dropdown trigger. The source’s `ListIcon` provides this page hook; the fixture records 5 tiles / 1 selected check / 5 menu buttons.
- **Community Themes catalog:** scope the Tabs root only when its first `[data-index="0"]` panel contains a small `data-slot="card"` with the source's CardContent preview frame and lazy image. This avoids assuming Base UI exposes `value` as a DOM data attribute (it exposes `data-index`). The fixture now models three source-shaped states: active theme (`outline`, disabled), installed-but-inactive (`default`, “启用主题”), and uninstalled (`default`, “安装主题”). Only enabled default actions receive the primary treatment; active/disabled state is asserted unchanged. Card density, preview aspect, badge geometry, hover, focus-visible and loading-disabled behavior are checked.
- **Relationship Graph surfaces:** `#chart > .relative > div.absolute:is(.w-64,.w-72)` reaches the legend and selected-node information panels only. The 44px avatar is scoped to the w-72 detail card; square community swatches live only under the legend/detail card. Fixture now includes the complete synthetic legend (community counts, degree/unknown markers, cross-community toggle, API/manual/historical edges, fetched count, updated time, and minimum-degree slider), plus a disabled refresh action. CSS intentionally does not target SVG nodes or circular data markers; the verifier uses actual SVG `<circle>` nodes and asserts radius, equal rendered width/height, fill/stroke, clip-path and mask unchanged.

## Deliberate misses / false-positive guards

- The Settings vertical TabsList is nested inside a PageScaffold fixture but is excluded by `[data-orientation="vertical"]` and remains style-identical. Side-rail tabs are outside `.vrcx-0-main-content`; entity-dialog tabs are outside the PageScaffold target scope. These misses are checked against the same fixture baseline.
- `[data-variant="default"]` multi-select chips are not in the outline ToggleGroup selector; Game Log chips remain unchanged.
- My Groups can share TileShell structure, but its toolbar does not satisfy the `svg.lucide-list` My Avatars hook (fixture uses `lucide-list-checks`); its TileShell is not matched. Friends Locations uses a globe icon for the alternate view, not this ListIcon hook.
- An `activity-card` without the `.activity-skin` page context is not targeted.
- A `data-slot="card"[data-size="sm"]` outside the Community Themes Tabs root and a similarly shaped information surface under `#other-chart` are deliberate misses; the verifier compares their computed styles before/after. Settings, entity-dialog, and side-rail exclusions remain unchanged.
- Only the selected outline Toggle item's decorative `::before` is disabled, under the same page-toolbar/variant/state scope, to eliminate the translucent input wash; no global pseudo-element rule or `::after` override is introduced. The selected face and bevel live on the control itself.
