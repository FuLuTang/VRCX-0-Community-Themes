## Avatar mask tiers and exclusions

- `--wd-avatar-cut` is the 32-grid midpoint-circle polygon. Use for large portrait faces (e.g. size-16 Activity lead, size-10 profile, 64px dialog icon).
- `--wd-avatar-cut-sm` is the 16-grid midpoint-circle polygon. Use for compact faces (e.g. size-7/size-9 Activity, default small popup/login portraits).
- `avatars-status-r9.css` covers source-shaped user profile/hovercard/dialog/activity/favorite faces. Activity `FadeInImage` image and direct fallback child both have `border-radius:0`, allowing the outer 32/16 polygon—not nested circles—to own the contour.
- `popups-r9.css`: unframed avatar image/fallback in menu, submenu, popover, select and combobox uses `cut-sm`; only `[data-size="lg"]` uses `cut`. Room-history `UserPickerRow` size-9 face uses `cut-sm`. Selectors exclude avatars with `[data-profile-decoration-asset]` or `[-inset-[18.75%]]`; parent menu rows containing such sibling frames are not clipped.
- `user-dialog-r9.css`: `.entity-dialog … div.absolute.bottom-3.left-3.z-30.size-16 > button[data-slot="button"]` and its direct `img` use the 32-grid `cut`. Keep the separate `ProfileAvatarFrame` node untouched.
- `login-r8.css`: under `[data-vrcx-0-surface="login-page"]`, default `data-slot="avatar-image"` and `data-slot="avatar-fallback"` use `cut-sm`; the direct image/fallback inside `[data-slot="avatar"][data-size="lg"]` uses `cut`.
- All these user-avatar faces lose avatar-owned border width, shadow, outline and theme pseudo-rings. VRChat-owned profile decorations are deliberately preserved. Do not generalize to `img`, `.rounded-full img`, generic Avatar primitives, world/group thumbnails, SVG graph circles, or `i.x-status-icon`.
- The apparent asymmetric lower-right “notch” was not a special clip-path: `avatars-status-r9.css` applies the symmetric 32/16-grid avatar circle, and `windose-runtime.css`’s additional side-panel/data-table `cut-sm` selector is already guarded by `:has(> span[class~="size-3.75"])`. The square patch came from the synthetic active-dot’s `bg-background` shell after the compiled join-me mask URL failed to resolve from the fixture’s `about:blank` origin. No production CSS change was needed. The fixture now shows a visible square lamp and a separate no-lamp avatar; the latter has the intact symmetric circle and no lamp-slot match.
